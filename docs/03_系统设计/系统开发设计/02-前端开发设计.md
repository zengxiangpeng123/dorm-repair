## 一、技术与目录

- Vue 3 + Vite + Vue Router + Element Plus + Axios。
- 三个独立应用，各自有 `package.json`、`vite.config.js`、入口、路由、API、会话和样式：
  - `app/student-web`：学生端，开发端口 5173。
  - `app/worker-web`：师傅端，开发端口 5174。
  - `app/admin-web`：管理端，开发端口 5175。
- 只读共享契约：`app/web/packages/contract`，包名 `@dorm/contract`，只放状态、事件和通用展示函数；不得放 session、router、API 客户端或页面。

```text
app/
├─ student-web/src/   api/ components/ constants/ views/student/
├─ worker-web/src/    api/ components/ constants/ views/worker/
├─ admin-web/src/     api/ components/ constants/ views/admin/
└─ web/packages/contract/src/index.js
```

## 三、请求与身份

- 所有请求经 `request.js`，禁止页面直接 `fetch` 或 `new axios()`。
- 身份只来自 `Authorization: Bearer <token>`；三端不得发送 `X-Actor-*` 或通过 `role` 参数切换身份。
- 请求成功剥出 `data`；失败统一抛出带 `status`、`code`、`detail` 的错误。
- 409 统一提示版本/状态冲突，并刷新详情；422 就地显示前置条件错误。
- 每个应用只接受自己的角色；登录后写独立 session key，并在进入受保护路由时调用 `/auth/me` 以服务端身份刷新本地会话。
- `OrderView`、请求 DTO、错误对象和枚举的字段定义以 `04-前后端API接口.md` 为准；目标返修审查字段为 `reworkReview`，后端未返回前不得自行伪造。

## 四、状态与组件规则

- 状态中文只从 `constants/status.js` 获取。
- 学生端五步进度由状态映射；`REWORKING` 显示在“上门维修”阶段，并额外展示返修链。
- `StatusPill`、`LevelPill`、`Plate`、`BottomNav` 为跨页复用组件。
- 页面按钮由接口 `allowed`、当前角色和 `version` 共同决定；不得只靠前端猜测。
- 手机页固定最大宽 430 px；管理端使用侧栏 + 密集表格。

## 五、目标返修审查 UI

- 学生详情页：验收区增加“申请返修”，填写原因后显示“返修审查中”，原单仍是待验收。
- 管理端：新增“返修审查”页签，列表展示单号、位置、学生原因、完工照、师傅、返修次数和等待时长。
- 审查抽屉展示原单时间线与照片，提供“确认返修”和“驳回申请”两个动作。
- 确认后刷新原单状态，并跳转/提示生成的 `-R1` 新单；驳回后显示原单继续正常验收。
- 所有动作携带 `version`；409 时关闭弹窗并刷新列表。

## 六、构建与验收

```powershell
cd app\student-web; npm install; npm run build
cd app\worker-web;  npm install; npm run build
cd app\admin-web;   npm install; npm run build
node app\tests\check-three-apps.mjs
```

构建前将 `$env:TEMP` 指向各应用 `.tmp`。三端 `strictPort` 固定端口；UI 改动必须逐端截图并人工检查 430 和 1440 两种宽度。
