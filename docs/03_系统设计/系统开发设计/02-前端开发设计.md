## 一、技术与目录

- Vue 3 + Vite + Vue Router + Element Plus + Axios。
- 入口：`app/web/src/main.js`、`App.vue`、`router/index.js`。
- API 唯一出口：`src/api/request.js`；业务封装：`src/api/orders.js`。
- 角色页面：`views/student`、`views/worker`、`views/admin`。
- 共享组件：`components/`；设计令牌：`styles/tokens.css`。

```text
src/
├─ api/          request.js、orders.js、session.js
├─ router/       三端路由
├─ constants/    状态、事件、计时器标签
├─ components/   状态胶囊、门牌、底栏
├─ views/        student / worker / admin / Entry / Lab
└─ styles/       tokens.css
```

> API 代理已指向后端 8082；启动脚本、测试脚本和页面截图均使用当前端口。

## 三、请求与身份

- 所有请求经 `request.js`，禁止页面直接 `fetch` 或 `new axios()`。
- 当前演示身份写 `X-Actor-Type`、`X-Actor-Id`；正式版改 `Authorization: Bearer <token>`。
- 请求成功剥出 `data`；失败统一抛出带 `status`、`code`、`detail` 的错误。
- 409 统一提示版本/状态冲突，并刷新详情；422 就地显示前置条件错误。
- 角色由路由前缀判定，切换页面时自动带对应身份，不在页面重复判断。
- `OrderView`、请求 DTO、错误对象和枚举的字段定义以 `04-前后端API接口.md` 为准；目标返修审查字段为 `reworkReview`，后端未返回前不得自行伪造。

## 四、状态与组件规则

- 状态中文只从 `constants/status.js` 获取。
- 学生端五步进度由状态映射；`REWORKING` 显示在“上门维修”阶段，并额外展示返修链。
- `StatusPill`、`LevelPill`、`Plate`、`BottomNav` 为跨页复用组件。
- 页面按钮由接口 `allowed`、当前角色和 `version` 共同决定；不得只靠前端猜测。
- 手机页固定最大宽 430 px；管理端使用侧栏 + 密集表格。

## 五、目标返修审查 UI

- 学生详情页：验收区增加“申请返修”，填写原因后显示“返修审查中”，原单仍是待验收。
- 管理端：新增“返修审查”页签，列表展示单号、位置、学生原因、完工照、师傅、返修次数和等待时长。
- 审查抽屉展示原单时间线与照片，提供“确认返修”和“驳回申请”两个动作。
- 确认后刷新原单状态，并跳转/提示生成的 `-R1` 新单；驳回后显示原单继续正常验收。
- 所有动作携带 `version`；409 时关闭弹窗并刷新列表。

## 六、构建与验收

```powershell
cd app\web
npm install
npm run dev
npm run build
npm run test:unit
```

构建前如遇 esbuild 临时目录问题，将 `$env:TEMP` 指向 `app\web\.tmp`。UI 改动必须执行截图脚本并人工检查 430 和 1440 两种宽度。
