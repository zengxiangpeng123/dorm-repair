## 一、职责边界

AI 只回答：故障类型、紧急程度、置信度、判断依据和是否兜底。它不连接 MySQL，不创建或修改工单状态，不参与派工。工单由 Java 后端根据 AI 结果创建和落库。

> AI 服务端口为 8001；本地启动配置、后端 `AI_SERVICE_URL` 和验收脚本已同步。

## 二、运行模式

| 模式 | 环境变量 | 行为 |
|---|---|---|
| `rules` | `AI_MODE=rules` | 只用关键词规则，毫秒级、断网可跑 |
| `llm` | `AI_MODE=llm` | 规则安全闸 + 兼容 OpenAI 的模型复核 |

配置模板：`app/ai/.env.example`；真实密钥写入 `app/ai/.env.local`，不得提交。正式模型为 `raccoon/sn-deepseek-v4-1-flash-1017`，网关通过 `AI_BASE_URL` 配置，默认不把密钥写入仓库或日志。

## 三、接口

| 方法 | 路径 | 入参 | 出参 |

| GET | `/health` | — | 状态、版本、规则数、运行时长 |

## 四、判断顺序

1. 安全类词直接定紧急：漏电、触电、打火、冒烟、起火、焦味、煤气味。
2. 按五类关键词判断类型：给排水、电气、电器、门窗家具、网络。
3. 给排水出现浸水风险词时提升为紧急。
4. 影响使用词提升为较急；低置信度保守升一档。
5. 规则安全闸命中时不再调用模型。
6. 非安全描述在 `llm` 模式下交给模型；模型输出必须通过类别、级别和 JSON 校验。
7. 模型失败、超时、格式错误或类型不合规时回退规则结果。
8. 每次后台复核记录任务审计：模型、尝试次数、耗时、错误码、结果是否写回；晚到或版本过期标 `SUPERSEDED`。

## 五、超时与降级

| 场景 | 处理 |
|---|---|
| 学生提交 | `fast=true`，只跑规则；Java 侧 1.5 秒拿不到即兜底 |
| 后台模型复核 | 30 秒超时，2 个守护线程，不阻塞 Web 请求 |
| 模型返回非 JSON | 按 `AI_MAX_RETRIES` 重试，默认最多 2 次，仍失败则规则兜底 |
| 认证失败/限流/上游异常 | 分别记录 `AI_AUTH_FAILED`、`AI_RATE_LIMITED`、`AI_UPSTREAM_ERROR` 等稳定错误码 |
| AI 服务不可用 | 返回兜底分类/级别，`levelSource=FALLBACK` 写入工单 |
| 结果为空 | 不覆盖当前工单，记录日志 |

兜底值：类别 `给排水`，级别 `较急`。依据中必须写明“AI 不可用”或“返回空内容”，方便追溯。

## 六、缓存与可观测性

- `classifier` 有最多 200 条的内存缓存，用于重复描述；仅缓存成功结果和安全闸门结果，模型故障/限流/超时等失败结果不缓存，避免恢复后仍返回旧兜底。
- 日志记录耗时、来源（rule-gate / llm / rule-fallback）和模型名。
- `/health` 暴露规则数和分类器统计；`/api/v1/ai/health` 由 Java 后端转发检查。
- `t_ai_review_task` 保存任务级审计；管理端通过 `GET /admin/ai-reviews` 只读查看。
- `SUPERSEDED` 表示模型结果晚到或工单版本已变化，任务保留但不覆盖工单。
- 不在日志中打印密钥、完整提示词或学生敏感信息。
