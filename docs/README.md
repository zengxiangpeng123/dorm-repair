## 四、目录与命名规则

```
docs\
├─ README.md          本页，文档索引
├─ 01_需求\           需求与口径：要做什么、为什么这么定
├─ 02_流程与状态\     图：流程图、状态机图（html 可缩放，png 可贴 PPT）
├─ 03_系统设计\       落地设计：接口契约，后续加数据库设计、架构说明
├─ 04_项目管理\       过程文档：流程计划、评审报告、笔记
└─ 99_存档\           上一版原件与交件打包，只读
```

- 编号前缀 `01_`–`04_` 是**阅读顺序**，不是重要程度；`99_` 表示只读。
- 文件名带编号的（`SYS-003_接口契约.md`）表示它是**受控文档**：有版本号、有状态、改动要留痕。
- 文件名不带编号的（`流程计划.md`）是工作文档，随用随改。
- 图一律 **html + png 成对放**。html 用来讲细节，png 用来贴 PPT。

## 五、加文档 / 改文档

1. **加**：先想清楚属于 01–04 哪一类，放进去；如果是受控文档，给它一个编号，并回本页第一章登记。
2. **改**：受控文档改完要升版本号、改更新日期、在文首状态栏如实标注；口径类改动必须走 `PM-001 流程计划` 第六章的变更控制。
3. **作废**：不要删。整份挪进 `99_存档\`，在本页第一章把状态改成「⛔ 已作废」并注明被谁取代。

**判断标准**：一份文档如果删掉之后，有人会做错事、或者要重新问一遍已经问过的问题——它就该留下来。反之就别写。
