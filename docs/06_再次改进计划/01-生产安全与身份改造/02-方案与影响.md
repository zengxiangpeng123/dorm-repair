# 02 方案与影响

## 目标方案

### 1. 身份唯一来源

- 删除 `Actor.of()` 的 `defaultId/defaultName` 身份猜测；缺账号直接拒绝。
- `AuthFilter` 只接受服务端验证后的身份；生产禁止 `X-Actor-*`。
- 所有工单详情、事件和命令同时校验角色与归属。

### 2. 可恢复会话

新增 `t_auth_session`：`id/token_hash/user_id/role/expires_at/revoked_at/created_at/last_seen_at/client_ip/user_agent`。

- 数据库只存 SHA-256 令牌摘要，不存原始 Bearer。
- 令牌随机生成，过期和撤销在每次请求校验；定期清理过期记录。
- 登录、登出、当前用户、重启恢复、多实例一致性均有测试。
- `/auth/system-token` 不作为用户接口；定时任务使用受控服务身份或内部调用。

### 3. 演示隔离

- `app.demo` 默认 false；生产 profile 不存在 `/demo/reset`、`/demo/advance`。
- 演示种子不自动进入生产；固定账号不得作为生产初始账号。
- 默认 root/123456 删除，生产缺少数据库凭据时启动失败。
- 生产 profile 强制 `app.store=mysql` 与 `app.file.metadata=mysql`，内存仓储配置启动即拒绝。

## 影响清单

| 层面 | 改动 |
|---|---|
| 后端 | AuthFilter、AuthService、TokenStore、Actor、生产配置、演示控制器 |
| API | 会话错误码、401/403、注销；不再支持冒名请求头 |
| 数据库 | 新增会话表与过期/撤销索引；清理生产演示账号 |
| 前端 | 登录恢复、401 跳登录、退出、会话过期提示 |
| 部署 | profile、密钥注入、服务身份、日志脱敏 |

## 兼容与回滚

先增加会话表并双轨读取，再切换生产；保留旧演示版用于测试。回滚应用但不删除会话表和用户数据。

## 风险

令牌泄露、会话固定、跨实例缓存、撤销延迟、误清生产账号、旧客户端兼容。
