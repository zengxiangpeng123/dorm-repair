# 02 方案与影响

## 目标结构

采用 npm workspace 管理三个应用和一个纯共享契约包：

```text
app/
├─ web/
│  ├─ package.json              workspace 根，不承载业务页面
│  ├─ packages/contract/        DTO、状态、错误、时间与格式纯函数
│  └─ ...                       仅构建与质量配置
├─ student-web/
│  ├─ src/main.js
│  ├─ src/router.js             只注册学生路由
│  ├─ src/api/                  学生 API + 学生会话
│  ├─ src/views/
│  └─ src/styles/
├─ worker-web/
│  ├─ src/main.js
│  ├─ src/router.js             只注册师傅路由
│  ├─ src/api/                  师傅 API + 师傅会话
│  └─ src/views/
└─ admin-web/
   ├─ src/main.js
   ├─ src/router.js             只注册管理端路由
   ├─ src/api/                  管理 API + 管理员会话
   └─ src/views/
```

## 现有文件归属矩阵

| 现有文件/目录 | 目标应用 | 处理方式 |
|---|---|---|
| `src/views/student/*` | `student-web` | 迁入学生独立 `views/` |
| `src/views/worker/*` | `worker-web` | 迁入师傅独立 `views/` |
| `src/views/admin/Home.vue` | `admin-web` | 迁入管理独立 `views/` |
| `src/components/BottomNav.vue` | 拆分 | 学生导航、师傅导航各自实现，管理端用侧栏 |
| `StatusPill.vue`、`LevelPill.vue`、`Plate.vue` | 按需共享 | 仅保留无业务副作用的纯展示组件 |
| `src/api/session.js` | 删除后拆分 | 每端独立登录态；共享包不存身份 |
| `src/api/request.js` | 拆分 | 每端独立 axios 实例和 401 处理 |
| `src/api/orders.js` | 拆分 | `studentApi`、`workerApi`、`adminApi` 各自只含本端命令 |
| `src/router/index.js` | 拆分 | 每端独立 router，只注册本端路由 |
| `src/styles/tokens.css` | 拆分 | 基础 token 共享；三端布局/页面样式分开 |
| `src/views/Entry.vue`、`Login.vue` | 拆分 | 各端独立登录页；跨端入口和演示工具退出生产 |
| `src/views/Lab.vue` | 移出生产 | 受控测试工具或独立测试站点 |
| `src/App.vue`、`src/main.js` | 拆分 | 每端独立应用壳和入口 |

## 依赖规则

```text
student-web ─┐
worker-web  ─┼─> shared-contract ─> 后端公开 API 契约
admin-web   ─┘

禁止：student-web ↔ worker-web ↔ admin-web
```

- 共享包不包含网络请求、token、localStorage、router、系统身份或任何命令函数。
- 通用状态标签可以作为纯展示组件评估共享；一旦包含角色分支就拆回本端。
- 学生、师傅、管理端分别使用独立 storage key 和登录会话。
- 生产端不提供跨端入口、身份切换器、系统令牌按钮或演示控制。

## API 与后端影响

- 不修改工单状态和数据库结构；以 `SYS-003` 和 `DEV-04` 为契约。
- 后端按角色限制 `/my/orders`、`/worker/*`、`/admin/*`，防止前端拆分后误以为已安全。
- 学生建单不直接调用 `/assign`；派工由后端内部任务/规则执行，避免学生依赖系统命令。
- 移除 API 客户端的 `opts.role` 临时换身份参数。
- 将演示入口和自检台移出生产三端，只保留受控测试工具。

## 构建与部署

- 三个独立 `package.json`、Vite 配置、构建输出和测试命令。
- 开发环境使用不同端口；生产环境使用不同路径或子域名，例如 `/student/`、`/worker/`、`/admin/`。
- 各自可构建、测试、发布、回滚；一个端发布不要求其他端重新部署。
- 共享契约升级先保持后端字段兼容，再逐端升级。

## 风险

- 迁移中重复代码漂移、共享样式破坏、会话串用、历史深链失效。
- 只拆目录不拆权限、误把前端隔离当安全、构建包仍包含他端页面。
