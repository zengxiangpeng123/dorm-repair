# 05 上线与回滚

## 发布步骤

1. 备份当前统一前端制品、路由配置和 Nginx 配置。
2. 先部署共享后端兼容 API，确认三端权限规则。
3. 在测试域名或受限路径部署三个新应用，检查深链与资源路径。
4. 分别灰度学生、师傅、管理端，观察登录、权限、错误率与业务完成率。
5. 三端稳定后再移除旧统一入口；不要提前删除旧制品。

## 路由兼容

- 为旧 `/student/*`、`/worker/*`、`/admin/*` 深链提供短期跳转或静态兼容。
- 旧 `/lab`、重置、快进、身份切换不进入生产应用。
- 通知、二维码和收藏链接必须验证目标端。

## 回滚

- 任一端异常，仅将该端切回旧制品，不回滚其他端。
- 共享契约不兼容时，优先回滚该端并保留后端兼容。
- 记录回滚时间、影响端、错误日志、用户范围和恢复验证。

## 上线门禁

三端不能互相打包、不能串会话、不能越权调用，独立部署/回滚通过，真实业务回归完成。
