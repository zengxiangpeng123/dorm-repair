# 05 上线与回滚

## 发布前

1. 评审变更、迁移 SQL、权限、配置和资源限制。
2. 备份数据库与文件对象，验证恢复路径。
3. 准备上一版本制品、旧配置和监控观察点。
4. 关闭生产演示功能，执行启动自检和 smoke。

## 发布与观察

先影子运行再小流量复核；模型故障切回规则，不回滚工单历史。

观察登录、权限、工单、返修、计时、AI/文件外部依赖、数据库错误、延迟和资源使用。至少完成一轮真实业务链验证。

## 回滚

- 优先切回旧应用版本或关闭新功能开关。
- 数据库新增结构保留，不执行破坏性回滚。
- 若旧数据已被迁移或不可逆处理，使用备份恢复并记录丢失窗口。
- 回滚后重跑登录、工单、返修、计时和文件/AI 验证。

## 上线结论

只有“实现、测试、部署、观察、回滚证据”齐全后，才可写“可试点”；正式生产准入还需通过第七次改进的试点与评审。
