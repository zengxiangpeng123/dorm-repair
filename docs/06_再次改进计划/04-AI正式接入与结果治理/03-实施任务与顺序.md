# 03 实施任务与顺序

## 任务拆解

| ID | 任务 | 验收出口 | 状态 |
|---|---|---|---|
| 01 | 冻结现状、字段、接口与迁移边界 | 影响清单与审查通过 | ✅ |
| 02 | 实现：生产模型配置、异步复核、版本与幂等、超时重试、任务审计 | 代码与迁移可构建 | ✅ 本地完成 |
| 03 | 同步 API、数据库和管理端 AI 审计表 | 字段一致，无演示假实现 | ✅ 本地完成 |
| 04 | 自动化、回归和真实模型验证 | 全部测试通过 | ✅ 本地完成 |
| 05 | 部署、观察、回滚演练与证据归档 | 完成上线审查 | ⬜ 待生产环境 |

## 实施顺序

1. 先冻结契约和现状，不先改数据库。
2. 先实现兼容写入和迁移，再切换读取与入口。
3. 先补权限、失败和回滚测试，再删旧路径。
4. 每个可回滚改动独立提交，提交信息写清行为变化。

## 禁止事项

- 禁止把生产改动留在本地未提交。
- 禁止提交密钥、真实用户数据和生产照片。
- 禁止用默认身份、demo 数据或关闭校验让测试通过。
