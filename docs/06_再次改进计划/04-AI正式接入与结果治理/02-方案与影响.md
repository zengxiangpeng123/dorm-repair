# 02 方案与影响

## 目标方案

- 正式配置 `AI_BASE_URL`、`AI_MODEL=workbuddy/deepseek-v4.1-flash`、`AI_API_KEY`；生产禁止本地明文密钥和默认明文 URL。
- 提交仍走快速规则；非安全命中才进入后台 LLM 复核，安全类永远规则优先。
- 复核任务记录 `task_id/order_no/order_version/input_hash/model/provider/status/attempts/requested_at/completed_at/error_code`。
- 结果合并只允许匹配当前工单版本和允许状态；过期、晚到、重复结果丢弃。
- 保存规则结果与模型结果，注明实际采用来源；confidence 是否入库随契约一次决定。
- 超时、429、无效 Key、非法 JSON、重试、幂等、服务降级均有指标和日志。
- `/health` 区分服务存活、模型可用、配置可用；真实连通性不能由“进程在运行”冒充。

## 影响清单

| 层面 | 改动 |
|---|---|
| AI | llm.py、classifier.py、配置加载、超时与错误分类 |
| 后端 | AiReviewService、复核任务、版本校验、调度与监控 |
| 数据库 | 复核任务表/结果记录、状态和重试索引 |
| API | AI 状态、结果来源、失败原因、内部任务权限 |
| 部署 | 密钥管理、出口访问、限流、费用和可用性告警 |

## 兼容与回滚

先影子运行不写业务字段，再小比例采用；故障切回规则。回滚不得覆盖已审计的模型结果和工单历史。

## 风险

无效密钥、供应商限流、数据出境与个人信息泄露、模型误判、超时堆积、重复写回、费用失控。
