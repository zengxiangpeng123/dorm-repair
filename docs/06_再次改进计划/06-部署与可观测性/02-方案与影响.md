# 02 方案与影响

## 目标方案

- 使用 `dev/test/prod` 配置分离；生产敏感配置必须注入，不得带默认口令。
- 提供容器化或受控服务部署、健康检查、资源限制、启动探针和优雅停机。
- 通过 Nginx/网关提供 HTTPS、域名、静态前端、API 反向代理与安全响应头。
- 输出结构化日志、请求关联 ID、错误码和慢请求；不记录口令、令牌、完整个人信息或照片内容。
- 暴露服务、JVM、数据库、HTTP、AI、文件存储指标；配置异常率、延迟、容量和任务积压告警。
- 数据库与对象存储定时备份，记录保留期、加密、恢复步骤和演练结果。
- 生产启动时校验配置、数据库版本、存储与依赖，不允许半可用服务接流量。

## 影响清单

| 层面 | 改动 |
|---|---|
| 代码 | 配置校验、健康检查、日志、指标、优雅停机 |
| 部署 | Dockerfile/Compose 或服务清单、Nginx、环境变量、资源限制 |
| 数据 | 备份、恢复、迁移版本和容量管理 |
| 运维 | 监控面板、告警、值班处理、故障和回滚手册 |
| 安全 | HTTPS、网络边界、访问控制、密钥与日志脱敏 |

## 兼容与回滚

先预发布后生产，保留旧制品、配置和备份；故障时切回旧版本，保留日志用于定位。

## 风险

误暴露端口、TLS 配置错误、日志泄露、监控缺口、备份不可恢复、资源耗尽、版本不一致。
