# 01 目标与范围

## 目标

用真实上传和受控访问替换 demo:// 占位照片，保证维修证据真实、完整、可追溯。

## 范围内

- 对象存储、上传校验、文件访问与生命周期的实现、文档、测试和发布证据。
- 保留现有业务语义：9 状态、13 转移；返修先审查后生成。
- 变更必须兼容已有工单历史，不覆盖原始事件、照片或审查记录。

## 范围外

- 不引入与宿舍维修闭环无关的社交、积分或扩展业务。
- 不把本迭代未部署的能力写成“已完成”。
- 不在生产环境继续使用默认账号、默认口令、演示令牌或演示重置接口。

## 业务不变量

1. 状态只能由 `OrderStateService.transit()` 推进。
2. 权限、归属、状态和版本校验不能被前端绕过。
3. AI、文件存储、通知和部署组件不能决定工单状态。
4. 关键副作用与状态变更保持事务一致。

## 目标状态

完成后应能用代码、测试和运行证据证明：用真实上传和受控访问替换 demo:// 占位照片，保证维修证据真实、完整、可追溯。
