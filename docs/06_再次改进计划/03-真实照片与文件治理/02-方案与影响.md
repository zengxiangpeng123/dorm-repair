# 02 方案与影响

## 目标方案

- 新增 `POST /files` 或预签名上传接口，服务端生成对象键，客户端不能决定最终 URL。
- 存储接口提供本地开发存储和 MinIO/OSS 生产实现，业务服务只依赖接口。
- 上传校验：扩展名与 MIME 双重校验、图片解码、大小和数量限制、随机对象名。
- `t_work_order_photo` 补 `object_key/original_name/mime/byte_size/sha256/visibility/deleted_at`；原 URL 仅作兼容显示。
- 默认私有读取；按工单归属和管理员权限生成短期下载 URL 或代理读取。
- 数据库保存元数据与对象键，存对象与元数据失败要补偿，孤儿文件定期清理。
- 前端使用 multipart/预签名上传，显示上传中、失败重试、删除受限与图片预览。

## 影响清单

| 层面 | 改动 |
|---|---|
| 后端 | FileStorage、FileController、文件服务、照片权限、异步清理 |
| 数据库 | 照片元数据列、对象键索引、访问与软删除 |
| API | 上传、下载、大小限制、错误码、旧 URL 兼容 |
| 前端 | New.vue、Task.vue、Detail.vue、真实文件控件和进度 |
| 部署 | 存储桶、凭据、访问策略、容量、备份和生命周期 |

## 兼容与回滚

旧 `demo://` 只读标记，禁止新写入；已上传对象保留。存储不可用时业务明确报上传失败，不能写假 URL。

## 风险

恶意文件、公开链接泄露、超大文件、对象与数据库不一致、存储费用、误删历史证据。
