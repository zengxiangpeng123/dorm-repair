# 02 方案与影响

## 试点方案

- 限定楼栋、人员和时间窗口，使用真实账号与真实工单，不导入固定演示数据。
- 明确业务负责人、技术负责人、故障联系人、服务时间和停用条件。
- 按真实链路验证提交、派工、到门、缺件、完工、验收、返修审查、归档和查询。
- 压测按目标用户数、并发和容量设定，报告 P50/P95/P99、错误率、吞吐和资源使用，不预设“已达标”。
- 安全验证覆盖越权、会话、上传、暴力登录、限流、HTTPS、敏感数据和旧接口旁路。
- 演练后端/AI/存储故障、数据库恢复、回滚、网络中断和备份不可用。

## 上线决定

| 结论 | 条件 |
|---|---|
| 通过 | 无致命/严重缺陷，核心指标达标，恢复演练和业务签字完成 |
| 限制试点 | 仅低风险问题，明确限制范围和修复日期 |
| 不通过 | 存在数据、安全、权限、核心业务或恢复能力问题 |

## 影响清单

| 层面 | 输出 |
|---|---|
| 业务 | 试点名单、培训、验收记录与问题清单 |
| 技术 | 压测报告、监控与告警记录、故障演练报告 |
| 数据 | 备份恢复报告、数据对账、隐私与保留策略 |
| 运维 | 值班、发布、回滚和应急联系人 |
| 项目 | 上线/不上线决定及签字证据 |

## 风险

真实数据泄露、试点范围失控、压测指标不透明、恢复失败、业务规则与现场不一致。
