## 实际改动

- 旧 `POST /orders/{no}/reject` 改为 `410 LEGACY_REJECT_DISABLED`，不再生成返修单。
- 新增 `t_idempotency_record`，按身份、方法、路径和 key 唯一；保存请求摘要与首次成功响应。
- 所有三端写请求自动携带 `Idempotency-Key`；后端统一拦截关键写接口。
- 管理员批准维修中撤销改为正式业务接口，要求存在学生撤销申请、必须填写原因。
- 状态机新增 `REPAIRING --CANCEL--> CANCELLED`，合法转移由 13 条调整为 14 条。
- 手动派工增加楼栋服务范围校验：师傅必须在 `t_worker_building` 中服务目标楼栋，否则返回 `WORKER_BUILDING_MISMATCH`，工单保持原状态。
- 配件到货后保留配件名称、金额与预计到货日期，确保超预算采购事实可追溯到归档。

## 2026-11-19 例外清单 kind 契约补齐

- `GET /admin/exceptions` 补齐设计文档已声明的 `kind=ALL|MISMATCH|OVER_BUDGET|REPEAT_REWORK|CANCEL_REQUEST` 参数。
- 指定 kind 时 `items` 和 `total` 按筛选结果返回，`counts` 仍保留四类全量计数；`ALL` 与不传参数行为一致。
- 非法 kind 返回 400，避免静默返回空列表掩盖调用错误；管理端 API 封装同步支持该参数。
- 新增服务测试覆盖过滤结果与全量计数并存；`ReworkReviewTest` 通过，管理端生产构建通过。
