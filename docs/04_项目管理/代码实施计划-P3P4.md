## 一、一句话目标

把"原型里那个跑在浏览器里的状态机"搬到服务器上：**页面只发命令，服务端只认 13 条转移**，
非法的一律 409，并且当着一屋子人的面能证明这点。

验收只有三句话：

1. `node app/server/index.js` 起来后，浏览器打开就是能用的系统（学生 4 页 / 师傅 4 页 / 管理端 1 页）；
2. 13 条合法转移全能走通，16 种非法组合全部 409 **且被拒后状态一个字节没变**；
3. 两颗 7 天计时器（T1 验收超时 / T2 归档）互不干扰，快进时间能当场演出来。

## 二、架构与目录

```
宿舍维修系统\
├─ app\                         ← 本期新增，全在这里
│  ├─ server\                   后端（Node 24 内置 http + node:sqlite，零第三方依赖）
│  │  ├─ index.js               启动：静态托管 app/web + /api/v1 路由
│  │  ├─ state.js               ★ 转移表 + 触发方 + next()，唯一的状态真相
│  │  ├─ orders.js              12 条命令的业务实现（含级联、返修、批量）
│  │  ├─ db.js                  node:sqlite 建表 / 迁移 / 种子
│  │  ├─ ai.js                  演示用定级（规则表，安全类优先，低置信升一档）
│  │  ├─ timers.js              T1/T2 扫描（含演示用的时间前移）
│  │  ├─ api.js                 路由 + 统一响应体 + 错误码映射
│  │  └─ tests\                 node --test（不起浏览器）
│  └─ web\                      前端（无构建、无框架，双击/直连都能跑）
│     ├─ index.html             入口 + 选择身份
│     ├─ student\ worker\ admin\ lab.html
│     └─ assets\ ui.css desk.css ui.js api.js
├─ prototype\                   ← 保留：离线原型（假数据 + 浏览器内状态机），不动
└─ docs\                        文档
```

**为什么零依赖**：答辩现场断网、换电脑、Node 版本不确定，`npm install` 是最容易死的一步。
`node:sqlite` 是 Node 22.5+ 内置的，Node 24 直接可用，`npm install` 一步都不需要。
（代价：`node:` 前缀的实验特性会打一行 warning，启动时关掉。）

## 三、状态机放哪（本期最关键的架构决定）

| | 原型 `prototype/` | 本期 `app/` |
|---|---|---|
| 状态机在哪 | 浏览器 `assets/app.js` | **服务端 `server/state.js`** |
| 谁能改状态 | 页面里任何一行 JS | 只有 `StateMachine.transit()` |
| 非法转移 | 前端抛异常（演示够用） | **服务端 409 + `from/event/allowed`** |
| 数据 | `localStorage` | SQLite 文件 `app/server/data/app.db` |

约束（写代码时照着做，`grep` 得到）：

1. 全项目只有 `state.js` 里有 `status` 的赋值语句；业务代码里搜不到 `order.status =`。
2. 转移表是 `{ from: { event: to } }` 纯数据，**不写 if-else 兜底**。
3. 一次转移 + 它的事件 + 它的级联（`ORIGIN_CLOSED`、生成 `-R{n}`）在同一个 SQLite 事务里。
4. 乐观锁：`UPDATE ... WHERE no=? AND version=?`，`changes===0` → 409 `VERSION_CONFLICT`。

## 六、数据模型（SQLite）

| 表 | 关键列 | 说明 |
|---|---|---|
| `orders` | `no` PK、`status`、`version`、`building`、`room`、`category`、`level`、`desc`、`window`、`worker_id`、`student_id`、`photos_before`、`photos_after`、`ai_*`、`parts_*`、`rework_of`、`rework_index`、`rework_count`、`no_show_count`、`created_at`…`cancelled_at`、`cancel_request_*` | 一张单一行；`version` 就是乐观锁 |
| `events` | `id` PK、`no`、`at`、`event`、`actor_type`、`actor_id`、`actor_name`、`manual`、`note`、`payload` | 只追加，永不修改 |
| `exceptions` | `id`、`kind`、`no`、`detail`、`status`、`created_at` | 四类；前三类由规则派生，第四类要落库 |
| `config` | `key`、`value` | 预算线等 |
| `seq` | `day`、`n` | 当日单号自增 |
| `users` | `id`、`role`、`name`、`building`、`room`、`team` | 演示账号：学生 / 师傅 / 管理员 |

**单号**：`BX` + `yyyyMMdd` + 3 位当日序号；返修单 `原单-R{n}`。
**时间**：全部服务端生成，`yyyy-MM-dd HH:mm:ss`，时区 `Asia/Shanghai`；演示"快进"用 `simNow` 偏移，不改进程时钟。

## 八、界面优化（手机端重做，这次按设备分工）

现状问题（原型自己评的）：手机页是"把桌面卡片压窄"，不是真手机页。

这次的做法：

1. **一屏一件事**：学生端首页只有三块——当前单、一个大按钮、我的报修；师傅端首页只有三个数字 + 今天要爬的楼。
2. **拇指可达**：主操作固定在底部 88px 安全区内，`min-height:48px`；顶部只放信息不放按钮。
3. **字号与层级**：正文 15px、次要 12.5px，标题只在一屏出现一次（不做 5 种字重）。
4. **状态色只有 9 个**，且**同一状态在三个端颜色一致**（学生看到的"待验收"和师傅看到的同一色）。
5. **照片位画成虚线框**（不占位空 div），空态给一句人话 + 一个下一步按钮。
6. **桌面端（管理端）继续用 `desk.css`**：左导航 + 密集表格，不做手机壳。
7. 所有页面 `prefers-reduced-motion` 下关掉过渡；断网时给出"连不上服务"的红条，不白屏。
