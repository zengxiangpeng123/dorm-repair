# 流程计划（防问题版）

> 适用于「宿舍维修系统 V5.0」从现有进度到答辩交付的全过程。
> 这份计划不是讲理论，只写两件事：**每个阶段必须交什么**、**什么情况下不许进下一阶段**。

---

## 一、这份计划防的是什么

四件事，按发生概率排序，每一条都在这份计划里有对应机制：

| # | 会出的问题 | 典型征兆 | 本计划的对应机制 |
|---|---|---|---|
| 1 | **口径漂移** | 界面上冒出"待师傅出发""已进楼""竣工待核验"；同一单在不同页编号不一样 | 第二章「唯一口径」+ 红线一 |
| 2 | **范围膨胀** | 做到一半加登录、加 AI 真调、加消息推送、加多楼栋 | 第三章「功能准入标准」+ 第六章变更控制 |
| 3 | **演示翻车** | 断网、单页打得开跳不动、数据被点乱回不去 | 红线三：断网可开、一键重置、种子数据覆盖 9 状态、5 分钟脚本 |
| 4 | **文档代码脱节** | 需求报告说的和原型做的不一致，答辩被问住 | 红线五：一次改动同步一处文档 |

## 二、唯一口径（先冻结，后面不许再改）

**这三样是标准，冲突时以它们为准，改它们要走变更单：**

1. `docs/01_需求/宿舍维修 · 项目完整闭环-V5.0.xmind` —— 业务闭环（8 段 + 三条线 + 三条判据）
2. `docs/02_流程与状态/工单状态机图-V5.0.html` —— **9 个状态 / 13 条合法转移 / 其余一律 409**
3. `docs/01_需求/需求报告-V5.0.docx` —— 功能、规则、验收标准

> 完整清单与优先级见 `docs/README.md`。

**已冻结的三项决定**（2026-11-17 定）：

| 决定 | 内容 |
|---|---|
| 打卡粒度 | 师傅点一次「进楼打卡」，背后**生成 N 条单级 `ARRIVE` 事件**；状态机语义不变 |
| 编号与状态词 | 单号 `BX + 8 位日期 + 3 位序号`（如 `BX20261117001`），返修单加 `-R1`；界面**只允许出现 9 个状态词** |
| 技术形态 | **无构建静态站点**：原生 HTML/CSS/JS，双击即开，断网可用 |

**状态词白名单**（只有这九个，多一个都不行）：
待派工、已派工、维修中、待配件、待验收、返修中、已完成、已关闭、已取消

## 三、阶段与门禁

每个阶段结束有一个**门禁**，门禁不过不进下一阶段。宁可在门禁上多花半天，也不要带病往前推。

| 阶段 | 干什么 | 必须交的 | 门禁（怎么算过） | 预估 |
|---|---|---|---|---|
| **P0 口径冻结** | 确认二章三样标准与三项决定 | 本章已列 | 团队每人都能背出 9 个状态、说出"为什么不能加审核中" | 已完成 |
| **P1 接口契约** | 把 13 条转移写成 API，定错误码 | `SYS-003_接口契约.md`：每个事件的路径、入参、出参、失败码、触发方校验 | 拿文档能写出前后端骨架，联调不靠猜 | ✅ 已产出 V1.0，待评审 |
| **P2 原型 9 页** | 学生 4 页 + 师傅 4 页 + 管理 1 页 | `prototype/` 可点击，全站共享一份 `data/seed.js` | 断网双击能开；一条单能从提交走到归档；故意点非法操作会当场报 409 | ✅ 已完成 |
| **P3 前端 demo** | 同一套页面接真接口 | `app/web/` | 换 `MOCK=0` 即连后端，页面代码一行不改 | 2 天 |
| **P4 后端 demo** | 13 条转移的 API + 数据库 | `app/server/` + 建表脚本 + 初始化数据 | 13 条合法转移逐条 200，非法转移逐条 409 | 3 天 |
| **P5 测试** | 按用例跑，出报告 | `TST-测试报告.md` + 缺陷清单 | 致命/严重缺陷清零；非法转移与越权用例全过 | 1 天 |
| **P6 验收与答辩** | 打包、脚本、演练 | 交付包 + 5 分钟演示脚本 + 一页 FAQ | 三个人分别照脚本走一遍，都能走通 | 1 天 |

## 四、各阶段检查单

按顺序勾，不勾完不算完。

### P1 接口契约
- [x] 13 条转移每条都有对应接口，事件名与状态机一致（`SUBMIT`/`ASSIGN`/`ARRIVE`/`NO_SHOW`/`FINISH`/`NEED_PARTS`/`PARTS_ARRIVED`/`ACCEPT`/`REJECT`/`AUTO_ACCEPT`/`ARCHIVE`/`CANCEL`×2）
- [x] 每个接口写明：谁能调（学生/师傅/系统/管理员）、前置条件、成功返回、失败码
- [x] 409 的响应体统一：`{ code: 409, from, event, allowed: [...] }`
- [x] 越权（非本单师傅打卡、非本人验收）单独列一条，明确返回码
- [x] 三条查询接口：我的工单、楼栋待办、例外清单
- [ ] **两条差异过评审**（G-01 级联关闭原单 / G-02 维修中管理员作废）—— 不过这两条，P4 会卡住

### P2 原型 9 页
- [x] 单一 `data/seed.js`，页面里没有任何硬编码假数据
- [x] 状态变化**只能**走 `App.fire()`，页面不许直接写 `status`
- [x] 9 个状态在种子数据里各至少 1 条
- [x] 待配件、返修 -R1、两颗 7 天计时器，三处都能演出来
- [x] 底部导航三端互通，点「切换」能回入口
- [x] 「重置数据」可用，点坏能一键还原
- [x] 108 种组合自检页（`lab.html`）跑出来是 13 条合法

### P3 前端 demo
- [ ] 页面文件与原型一一对应，不重写视觉
- [ ] 所有请求走统一 `api.js`，不散落 `fetch`
- [ ] 网络失败有兜底提示，不白屏
- [ ] 时间不再本地伪造，全部来自服务端

### P4 后端 demo
- [ ] 状态字段只能由状态机模块改，业务代码里搜不到 `set status`
- [ ] 每次转移都落一条 `work_order_event`（事件、操作人、manual、时间、备注）
- [ ] 乐观锁：并发两个请求只有一个成功，另一个 409
- [ ] 两个计时器由定时任务驱动，参数可配置（168 小时 / 7 天）
- [ ] 预算线是配置项，不写死在代码里

### P5 测试
- [ ] 13 条合法转移逐条有用例
- [ ] 6 条以上非法转移逐条验证 409
- [ ] 越权用例不少于 4 条
- [ ] 并发用例 1 条（同一单同时打卡）
- [ ] 计时器用例 2 条（T1 自动验收、T2 自动归档，可缩时间跑）
- [ ] 缺陷登记表：编号、现象、复现步骤、状态

### P6 交付
- [ ] 交付包目录干净（无临时文件、无 reference 以外的冗余）
- [ ] 5 分钟演示脚本：谁点哪里、说哪句话，逐条写死
- [ ] FAQ 一页：为什么不能加「审核中」、为什么两个 7 天、为什么管理端没有状态位
- [ ] 断网演练一次

## 五、五条红线（越线就是返工）

**红线一｜口径**：9 状态 13 转移是唯一标准。想加状态、加事件，**先改状态机文档并评审**，再动代码。未评审的新状态词一律视为 bug。

**红线二｜范围**：新功能进入本期，必须**落到闭环三条判据之一**（不用人点头 / 管理端大部分时间是空的 / 零人工完成率高且返修率低）。落不到的一律进"二期清单"，不进代码。

**红线三｜可演示**：任何一页交付前，必须能在**断网状态**下双击打开并且跳转正常。依赖 CDN、依赖本地服务器、依赖浏览器缓存的，全部不算过。

**红线四｜数据单一**：全站只有一份种子数据、一处状态机实现。出现第二份，立刻删。

**红线五｜文档同步**：改动涉及状态、字段、规则时，**同一次提交里**同步改对应文档的一处。不允许"先写完代码再回头补文档"。

## 六、变更控制（想加需求时怎么走）

不是不许加，是必须留痕。三步，口头说不算：

1. **提变更单**：想加什么、为什么、不做的后果。
2. **影响评估**：动到状态机吗？动到接口吗？要几天？砍什么换？
3. **决定并记录**：进本期 / 进二期 / 不做，写进变更记录，注明日期与理由。

**默认结论：进二期。** 除非它能证明"不做闭环就不成立"。

## 七、四个评审点

| 评审 | 时机 | 看什么 | 谁参加 |
|---|---|---|---|
| 需求评审 | P0 之后 | 每条需求是否可验证、是否覆盖闭环 | 全员 |
| 设计评审 | P1 之后 | 接口能否支撑 13 条转移、错误码是否够用 | 前后端 |
| 代码评审 | P3/P4 期间 | 状态改动是否只走状态机、有无重复实现 | 互相看 |
| 验收评审 | P5 之后 | 用例是否全过、演示脚本是否走得通 | 全员 |

每次评审留一份结论：通过了什么、留下什么问题、谁负责、什么时候关。

## 八、风险清单

| 风险 | 征兆 | 应对 |
|---|---|---|
| 原型越做越大 | 页面数超过 9、开始加设置页/消息中心 | 回到 P2 清单，超出的一律进二期 |
| 后端拖成无底洞 | 一周还没跑通第一条转移 | 先把 13 条转移跑通，其余能力（搜索、导出、权限细化）全砍 |
| 演示环境不可控 | 答辩机器没装东西、没网 | 无构建 + 断网演练 + 一个 U 盘备份 |
| 数据被点乱 | 演示到一半状态全错 | 开场先「重置数据」，演示顺序固定 |
| 分工不清 | 两人改了同一处、或都以为对方在做 | 每日 10 分钟同步，只讲三句 |

## 九、每日节奏（每天 10 分钟，别省）

每人三句话：**昨天做完什么、今天做什么、卡在哪。**
卡住超过半天的问题，当天说出来，不要自己憋到截止日前。

## 十、Definition of Done（每条都成立才算"做完"）

- 功能：按需求报告的验收标准逐条对过
- 状态：只用 9 个词，只走 13 条边
- 数据：一份种子/一处状态机，没有第二套
- 演示：断网可开、可重置、5 分钟脚本走得通
- 文档：相关章节已同步
- 测试：对应用例通过，缺陷已登记
