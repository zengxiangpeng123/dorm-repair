1. G0–G7 全部完成，WBS 的预估、实际和状态已回填。
2. 后端 8082、AI 8001、前端代理 8082 验证通过；全仓搜索无遗漏旧端口。
3. 迁移期 16 表、最终 15 表口径在文档、脚本和 CG 中一致。
4. `v_user_account` 删除顺序、floors 三处改造和数据库回滚已验证。
5. `mvn test`、AI pytest、前端 build/测试、端到端脚本全绿。
6. 管理员可推 REJECT；审计事件不改变状态；T1 暂停/重置通过。
7. 自动派工只按楼栋和主负责师傅；无师傅返回 422 且保持 PENDING。
8. `build_docs.py` 旧口径已改，CG01–CG14 已重生成。
9. 旧 `t_user`、旧端口、旧 `/reject` 有保留或删除结论。
10. 计划文件、归档旧文件和代码删除已进入同一版本管理提交。

## 三、回滚步骤

- 视图删除前：切回 `v_user_account` 和旧 mapper。
- 视图或 `t_user` 删除后：恢复数据库备份，不宣称兼容视图可回滚。
- floors 删除前：保留旧列一个发布周期；删除后回滚走备份。
- 审查或计时失败时停止新路径写入，保留新表数据。
- 回滚后重跑登录、建号、改口令、建单、返修、派工和归档 smoke。
- 回滚版本不重生成 CG，避免交付物混用。

## 四、风险清单

| 风险 | 影响 | 应对 |
|---|---|---|
| 阶段工时与 WBS 不一致 | 排期失真 | 阶段表列“包含任务”，按 17.5d 对账 |
| 先删 `t_user` 后删视图 | 视图失效 | 固定“停写→删视图→删表”顺序 |
| floors 三处未同步 | reset/meta 失败或双重事实源 | schema/data/MetaController 联合检查 |
| 审查轮次覆盖 | 丢失历史或唯一键冲突 | attempt_no + 可空 rework_index |
| TRIGGER 漏加审计事件 | 学生申请直接 403 | T04b + 权限单测 |
| createRework 审计主体错误 | 事件回放不一致 | 新路径独立，子单 SUBMIT 归学生或新增专用事件 |
| 端口漏改 | 联调与 AI 协作失败 | 端口清单 + 全仓搜索 8080 和 8000 |
| 单人排期过载 | 质量下降 | 18 日计划，D1–D18 不超 1 人日 |
| CG 生成器旧口径 | 答辩材料错误 | T15 重生成并校验 |

## 五、版本管理

- G0 门禁要求计划文件、`old/` 归档和代码删除进入 Git 版本管理。
- 归档必须在同一提交中包含“旧文件删除 + old/ 新文件新增”，否则 `git checkout` 可恢复旧计划。
- 最终提交前检查 `git status` 无非预期未跟踪文件。

## 六、最终验收

主链、返修审查、管理员 REJECT、审计事件、T1、自动派工、16/15 表数、floors、端口、字段契约、CG 和回滚全部有通过证据，才允许关闭 G7。
