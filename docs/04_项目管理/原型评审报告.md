# 原型评审报告：Stitch 12 屏 → 我们的 9 页

- 评审对象：`prototype/reference/stitch-12屏/`（Google Stitch 导出，只读存档）
- 评审依据：`docs/01_需求/需求报告-V5.0.docx`、`docs/02_流程与状态/工单状态机图-V5.0.html`、`docs/01_需求/宿舍维修 · 项目完整闭环-V5.0.xmind`
- 评审日期：2026-11-17

## 一句话结论

**视觉可以直接用，业务要重新装。** 它读懂了"三类例外""零审批""按楼栋跑"这几个概念，但往下自己发挥了：管理端做成了指挥大屏、加了一套工分工资体系、报修页漏了「可上门时段」、打卡粒度是楼栋级而不是单级。**12 屏保留 9 页，删 2 屏、合并 3 屏、新增 1 屏。**

---

## 一、这份原型是什么

技术形态：12 个**互相独立的单页 HTML**，每个都通过 Tailwind CDN 引入样式，假数据各自写在页面里。

三个硬伤，决定了它不能直接当原型用：

| 硬伤 | 具体表现 | 影响 |
|---|---|---|
| 假数据 12 份复制 | 张同学、李建国、7 号楼 402 在十几屏里反复硬编码，改一处要改十二处 | 演示时数据前后矛盾（同一单在不同页编号不同） |
| 依赖 CDN | 全部样式走 `cdn.tailwindcss.com` | **答辩现场断网就白屏** |
| 壳页跑不起来 | 根目录 `index.html` / `student.html` / `worker.html` / `admin.html` 引用 `assets/styles.css`、`data/seed.js`、`assets/*.js`，但这几个目录**根本不存在** | 三端入口点进去是空白，只能一屏一屏单独打开 |

另外：单号有三套写法（`#240508`、`#GD-20231108-042`、`GD-20231108-019`），状态词有五种说法，故障分类是"强弱电/供排水暖/门锁家具/建筑防水"——**和我们五类口径（给排水/电气/电器/门窗家具/网络）不是一套**。

### P1 建议改（工程与一致性）

- 12 份硬编码假数据 → 抽一份 `data/seed.js`，所有页读同一份
- Tailwind CDN → 本地 CSS（`assets/ui.css`），断网可用
- 照片"最多 4 张 + 短视频" → 收敛为 1 张必填
- 评价体系（4.9 分 / 好评率 / 热词云 / 点赞）→ 收敛为"电子签字"，评价不进口径
- 手机 390 宽固定 → 加桌面自适应（答辩投屏多数是 1920 宽）
- 品牌"宿修宝 / 清晏大学" → 产品名可留，学校名改中性，避免和真实学校冲突

### P2 保留（明确不动的资产）

1. **师傅端"一栋一栋楼跑"的动线**：按楼栋排队 → 进楼 → 楼层分布 → 逐间卡片。这是全原型最值钱的部分，比我们原来的设计好，直接留。
2. **学生首页那句话**："拍一张、说一句，剩下的它自己跑"——一句话把零审批讲清楚了。
3. **视觉语言**：状态胶囊、纵向时间线、底部三大按钮、卡片阴影层级。

## 五、需要拍板的三个决策

### D1　打卡粒度（影响状态机）

- **方案 A（建议）**：按钮仍叫「进楼打卡」，一次点击背后**生成 N 条单级 ARRIVE 事件**。师傅只操作一次，状态机语义不破，撤销边界、人工标记、零人工完成率全部照常算。
- 方案 B：改 SYS-004，新增"楼栋到场"事件，ARRIVE 改成批量。代价是丢掉"该单属于此师傅"这条前置校验。

### D2　单号与状态词

统一为 `BX + 日期 8 位 + 3 位序号`（`BX20261117001`）；界面只用 9 个状态词，禁止出现"进楼""待出发""竣工待核验"这类临时说法。返修单在原单后加 `-R1`。

### D3　技术形态

- **方案 A（建议）**：**无构建静态站点**——原生 HTML/CSS/JS，一份 seed.js，双击就能开，断网可用。课设答辩最稳。
- 方案 B：Vite + React，工程化好但要装 Node、要 build，答辩现场多一个失败点。

## 六、改造顺序（每步可验收）

1. **骨架**：`prototype/index.html` 三端入口 + `assets/ui.css`（从 DESIGN.md 提炼令牌）+ `data/seed.js`（一份假数据，含 9 状态工单样本）+ 三个端壳页可互相跳转。验收：断网双击能打开，能跳转。
2. **学生端 4 页**（先 P2 报修，它决定数据从哪来）。验收：提交后能在 P3 看到新单。
3. **师傅端 4 页**（W2、W3 是核心）。验收：打卡 → 完工照 → 进入待验收。
4. **管理端 1 页**。验收：三类例外各有样本，撤销审批能改状态。
5. **逐步替换**：每改完一页，删掉 reference 里对应的旧屏引用（旧屏本体不动，只读存档）。

## 七、工程约定

1. `prototype/reference/` **只读**，永不修改。它的作用是答辩被问"你们改了什么"时能当场对比。
2. `prototype/` 用假数据，`app/` 连真数据库，两者不混。
3. 文档只放 `docs/`，代码只放 `prototype/` 和 `app/`。
