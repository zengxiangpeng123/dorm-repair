# 答辩演示脚本（5 分钟，当前三端版本）

> 目的：证明工单闭环、状态约束和异常审查确实可运行，而不是只展示页面。
> 基线：Spring Boot 8082 + FastAPI 8001 + MySQL；学生端 5173、师傅端 5174、管理端 5175。演示前确认 `APP_DEMO=true`、MySQL 与三端服务已启动，并用管理员重置演示数据。

## 0 开场与登录（20 秒）

> “这套系统解决的是报修后没人管、过程说不清。学生、师傅和管理员使用三个独立应用，账号登录后只能看到自己有权限的操作。”

打开学生端 `http://localhost:5173/student/`，用 `S001 / dorm@2026` 登录。说明正式鉴权为 Bearer Token，三端会话互相隔离；`X-Actor-*` 只在测试/演示开启，生产必须关闭。

管理端自检台展示状态矩阵：**9 个业务状态、14 条合法转移、10×14=140 格，126 格非法**。`REJECT` 只能由管理员触发；学生只提交返修申请。

## 1 主闭环（90 秒）

1. 学生端点“我要报修”，选择现场照片并上传，描述“洗手台下面漏水，柜子里全是水”，选择可上门时段并提交。
2. 展示工单号、AI 定级依据和自动派工结果。说明提交时快速规则定级，后台使用 `raccoon/sn-deepseek-v4-1-flash-1017` 异步复核；模型不可用会降级，不阻断报修。
3. 师傅端 `http://localhost:5174/worker/` 用 `W0428 / dorm@2026` 登录，进楼打卡，再进入工单上传真实完工照片并提交。
4. 学生端确认待验收状态和 T1 计时，签字后转为已完成，展示 T2 计时。

> “照片不是占位 URL：上传后通过受权文件接口读取。生产 S3 桶、HTTPS 和目标环境容量仍待部署验证，本地验证不冒充生产验收。”

## 2 非法转移与版本冲突（60 秒）

在管理端自检台选一张 `ASSIGNED` 工单，直接触发 `FINISH`：

- 返回 `409 STATE_CONFLICT`，包含 `from/event/allowed`；
- 再次读取详情，状态与版本均未变化；
- 说明 `403` 是权限拒绝，`409` 是状态冲突，`422` 是已有转移但照片、原因等前置条件不满足。

## 3 返修与撤销（70 秒）

1. 学生对待验收工单提交返修申请，原单仍保持 `VERIFYING`，不生成新单。
2. 管理端 `http://localhost:5175/admin/` 用 `A001 / dorm@2026` 登录，在返修审查中批准：原单转 `REWORKING`，生成 `-R1`；若是误报则驳回，不生成新单并恢复验收计时。
3. 展示旧 `/reject` 返回 `410 LEGACY_REJECT_DISABLED`，说明没有绕过管理员审查的兼容旁路。
4. 学生进楼后只能申请撤销；管理员在例外清单填写决定原因并批准，`REPAIRING + ADMIN_CANCEL → CANCELLED`，不是 501。

## 4 看板与证据（40 秒）

展示四类例外：数据对不上、超预算采购、反复返修、撤销申请。主指标是**无管理员介入完成率**：已完成/已关闭工单中没有 ADMIN 角色事件的占比；事件级 `manual=0` 只作诊断，不把结构性恒 0 当成主目标。

当前本地证据：Java 132 tests（0 failures / 0 errors，2 skipped）、AI pytest 31、旧共享前端 Vitest 8、原型自测 34、三端构建和本地预验收通过。读压测为 200 请求、并发 20，P95 270.36 ms、错误率 0；这些不是目标环境生产指标。

## 5 翻车处理

| 现象 | 处理 |
|---|---|
| 后端未启动 | `cd app\server; mvn -q -DskipTests package; java -jar target\dorm-repair-server-1.0.0.jar`，先检查 MySQL 与 `DB_*` 配置 |
| AI 未启动 | `cd app\ai; python -m uvicorn app:app --host 127.0.0.1 --port 8001`；确认 `/health` 中 `llmEnabled=true` 与正式模型 |
| 页面无法访问 | 分别确认学生 5173、师傅 5174、管理端 5175，并检查 `/api` 代理到 8082 |
| 数据被点乱 | 仅演示环境调用 `/api/v1/demo/reset`，返回 `seeded=11`；禁止在生产开启演示接口 |
| 想证明后端 | `cd app\server; mvn -q test`，再按环境运行 `app\server\tests\m1-chain.ps1` 至 `m5-auth.ps1` |
| 想证明原型 | `node prototype/tests/selftest.js prototype`，应为 `34 通过 / 0 失败` |
