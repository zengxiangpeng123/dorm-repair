# 答辩演示脚本（5 分钟，一次跑完）

> 目的：**不是展示功能多，而是当场证明三件事能成立。**
> 演示环境：本机 `node app/server/index.js` + 浏览器 <http://localhost:5173/>，断网也能跑。
> 演示前先在入口页点一次「重置演示数据」，保证每条都是第一次。

---

## 0 开场（20 秒）

> "这套东西解决的不是'报修没入口'，是**报了没人管、管了说不清**。
> 我们只保证三件事：流程自己走完、走不通的路当场被拒、每一步都留痕。
> 对外不讲'更快'、'更好'——那两个我们现在证明不了。"

点 **/lab.html**（自检台），先说结论：**9 个状态、13 条能走的边、其余 107 种组合一律拒绝。**

---

## 1 必证一号：一条链自己走完（90 秒）

**学生端 → 提交**

1. `/student/` → 点「我要报修」
2. 点一下"拍照"（+1 张）→ 描述写 **"洗手台下面漏水，柜子里全是水"**
3. 页面**实时**跳出：故障类型 `给排水`、紧急程度 `紧急`、置信度、判断依据（"命中浸水风险，按安全类直接定紧急"）
4. 可上门时段选「下午」，提交 → 拿到单号 `BX2026...`，同时**系统自己派给了本楼栋师傅**

> 说一句："紧急程度学生不能选，是系统判的，而且判完把依据留在单子上——出事能查为什么这么判。"

**师傅端 → 上门**

5. `/worker/` → 点「进楼打卡 · 东区7号楼」（一次点击，本批 N 单一起转"维修中"）
6. 待办卡片点进单间作业 →「① 能进场吗」点"门开着，进去"→「② 能当场修好吗」点"修好了"→ 选"更换软管"、拍完工照、提交

**学生端 → 验收**

7. 回 `/student/`，这张单变成"待验收"，页面上出现 **T1 倒计时：还剩 6 天 23 小时**
8. 点「确认修好并签字」→ 状态变"已完成"，同时出现 **T2 倒计时：还剩 7 天**

> 说一句："两颗 7 天计时器，起点不一样：T1 从师傅交完工照起算，T2 从学生签字起算。同一张单不会同时有两颗。"

---

## 2 必证二号：非法转移当场拒，而且一个字没变（60 秒）

回到 **/lab.html**：

1. 下拉里选一张 **「已派工」** 的单（不是待派工——待派工没有师傅，点师傅的按钮只会拿到 403 权限拒绝，那是另一件事）
2. 左列「会被拒的事件」里点 **FINISH**：按钮上就写着"现在点应该是 409 状态机拒绝"
3. 结果面板明确显示：`HTTP 409`、`状态「已派工」不接受事件「完工提交」`、`这单现在只能做：ARRIVE / NO_SHOW / CANCEL`，最后一行还替你把话说了：**工单一个字没动：仍是 ASSIGNED，version 仍是 2**
4. 再点一次「重新取一遍表」——状态与 version 都没动

> 说一句："页面里没有一处 `status = ...` 赋值，改状态只有一条路：先查这张表，查不到就抛 409。
> 顺便把两种拒绝分清：**409 是状态机说这条边不存在，403 是身份不够**，都不是 200。
> 这就是为什么这套东西不会出现'单子莫名其妙变成已完成'。"

**再补一刀（可选）：** 同一张单快速连点两次"派工"，第二次会拿到 `409 VERSION_CONFLICT`「状态已变化，请刷新」——乐观锁。

---

## 3 必证三号：管理端平时是空的（60 秒）

打开 **/admin/**（电脑页）：

1. 四个数字：在办 / 待归档 / 例外待看 / **零人工完成率**
2. 右栏「例外待看」只有四类：数据对不上、超预算采购、反复返修、学生申请撤销 —— **其余一律不露**
3. 点「学生申请撤销」那条的「批准撤销」→ 页面提示 **接口返回 501：这条边要等变更单 #001 批准**
4. 「超预算采购」那条：480 元 > 200 元线。**把配件收下（`/worker/parts`），这条记录仍然留着**——花过的钱不会因为流程往前走就自己消失，一直到单子归档

> 说一句："唯一需要人点头的地方，我们把它的接口故意留在 501。
> 因为我们发现 `维修中 → 已取消` 这条边在状态机里是禁止的——要开它必须先过变更单，不能偷偷加。"

5. 再点顶栏「快进 7 天」→ toast 报 "自动验收 X 单、自动归档 Y 单"；回到监测台，待归档清了、最近归档多了几行

> 说一句："管理端大部分时间应该是空的。它一忙，说明流程在漏。"

---

## 4 收尾（40 秒，讲限制，不讲愿景）

> "能证明的：链条、409、两颗计时器、返修 -R1、四类例外。
> 不能证明的我们写在 README 里：真实并发没压测、AI 是词表规则不联网、照片是占位串、只有两栋楼的种子数据。
> 下一步不是堆功能，是拿这三条去现场蹲 20 单，先量出白跑率和平均修复时长——没有基线，讲价值都是空的。"

---

## 附：如果现场翻车怎么办

| 现象 | 一句话处理 |
|---|---|
| 页面打不开 | 先看终端有没有跑起来；`node app/server/index.js` 一条命令重启，数据在 SQLite 里不会丢 |
| 数据被点乱了 | 入口页「重置演示数据」，回到 14 张单 11 个账号 |
| 想证明后端而不是页面 | `node --no-warnings app/server/tests/api.test.js`，当场看 `pass 17 / fail 0` |
| 想证明原型也能跑 | `node prototype/tests/selftest.js prototype`，当场看 `34 通过 / 0 失败` |
| 被问"这是前端硬编码的吧" | 打开 `/lab.html` 改一个事件，或断网刷新页面——数据全来自 `/api/v1`，前端没有一份假数据 |
