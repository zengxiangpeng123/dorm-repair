# 原型自测（无头，不需要浏览器）

`selftest.js` 把 `data/seed.js` 和 `assets/app.js` 装进一个假的 `window` 里，直接跑状态机，
用来证明三件事——也就是这份 demo 唯一需要证明的三件事：

1. 一条链能不能自己走完（提交 → 派工 → 打卡 → 完工 → 验收 → 归档），中间不缺步、不漏步；
2. 非法转移是不是**当场**被拒（409），而不是靠人记得不该点；
3. 两颗 7 天计时器是不是各算各的（T1 从完工时间起算、T2 从签字时间起算）。

## 怎么跑

在 `prototype` 目录下（Windows，Node 18+）：

```powershell
node tests/selftest.js .
```

最后一行必须是 `结果：34 通过 / 0 失败`，退出码 0。

## 覆盖了什么

| 段 | 验的东西 |
|---|---|
| 1 | 建单走 `NEW → PENDING`；单号 `BX+8位日期+3位序号`；照片 0 张、描述 <4 字被 400 拒；AI 安全类优先定级；依据落库；全链 6 个副作用字段（assignedAt / arriveAt / finishAt / signAt / closedAt / statusAt）；每个事件都有 `manual` 标记 |
| 2 | 16 种非法转移全部 409，且**被拒后状态一个都没变**（这条比"能拒"更重要） |
| 3 | 触发方校验（学生不能派工、系统不能提交）；撤销边界——待派工可撤、师傅进楼后撤不了 |
| 4 | 返修：原单转返修中、生成 `-R1` 新单、新单从待派工入队、`rework_of` 指回原单、紧急度升一档 |
| 5 | T1 只认 `finishAt`、T2 只认 `signAt`；一张单不会同时有两颗计时器 |
| 6 | 到点才动：不动时间不会自动验收；快进 8 天后待验收自动确认（`manual=0`）、已完成自动归档 |
| 7 | 例外清单只出约定那几类；零人工完成率始终在 0~1 |

## 一句话说明（答辩时用）

> 这个 demo 里改工单状态只有一个入口 `App.fire()`，它查一张 13 行的转移表；
> 表里没有的组合一律抛 409。页面一行 `status = ...` 都没有。
> `tests/selftest.js` 就是拿这 34 条断言去撞这张表的。
